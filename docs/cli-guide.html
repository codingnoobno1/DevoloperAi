🚀 5-Minute Quick Start

Syncro CLI — User Guide

One command-line tool to clone, analyse, document, and fix any project. It builds a local map of your code, answers questions about it, and quietly fixes setup errors for you — fully offline, and smarter when an AI model is available.

📦 Install

Syncro CLI ships with the Syncro Desktop app. One command registers it on your system PATH so you can type syncro from any folder.

1
Register on PATH Soon
Auto-elevates (UAC) and adds the CLI to your machine PATH, then tells open terminals to refresh — no reboot.
PowerShell / Terminal
> syncro install
2
Verify
Open a new terminal and check the version + a quick environment health report.
Terminal
> syncro doctor
✓ Node.js 20.11   ✓ Python 3.12   ✓ .NET 9   ✓ Git 2.44
Environment looks healthy.
Manual fallback: if syncro install isn't in your build yet, add the app's install folder to your PATH by hand (System → Environment Variables → Path), then reopen your terminal.

🚀 Your First 5 Minutes

The core loop: bring a project in, let Syncro understand it, then ask it questions and generate a report. Everything is stored locally in a .syncro_db folder.

1
Clone a repo Live
A crash-safe clone that runs in its own process and reports progress.
Terminal
> syncro git clone https://github.com/acme/viking-api.git
2
Analyse it Preview
Scans the source into an AST, detects the language & framework, finds endpoints and DTOs, and tokenises everything into a local searchable index.
Terminal
> cd viking-api
> syncro analyse

See what it learned Preview
Prints the project straight from the local DB — in its tokenised/vector form: top terms, entities, endpoints.

Generate a report Soon
Builds a PDF/JSON report from what's already in the DB — endpoints, DTOs, dependency graph, ports. No re-scan.

🔁 The Self-Healing Loop

When a task fails, Syncro doesn't just stop. It reads the error, looks up a known fix in its local database, reuses a fix script if it has one, and loops — bounded, and never silently changing your code.

📡 Works Offline · Better With AI

Syncro is designed to be useful with zero internet, and to quietly level up when a model is reachable.

🔌
Offline (always)
Cloning, analysing, AST queries, reports, keyword-based error fixes and script reuse all run locally from your .syncro_db. No model required.
🤖
With AI (optional)
If a local model is running (default localhost:3020), Syncro adds richer explanations, code generation, and learns new error fixes. It probes quickly and falls back gracefully if the model is down.
Force offline anytime: add --no-llm to any command to skip the model and use only local knowledge.

🔒 What Syncro Will & Won't Do

Syncro is built to be safe to leave running. The AI proposes — the deterministic core disposes.

🚫
Never auto-runs AI code
Generated scripts & patches are previewed and applied only with your --yes/approval. A new script's first run always asks.
🧴
Secrets stay home
API keys, tokens and connection strings are redacted before anything is sent to a model, and never written into stored scripts.
🛡️
Dangerous scripts blocked
A safety scanner refuses destructive patterns (rm -rf /, format, fork bombs, pipe-to-shell) — they can never auto-run.
🔁
No runaway loops
The self-healing loop is bounded by a max-attempts limit and hands off to you instead of looping forever.
📋
Everything is audited
Every script run, fix and model call is logged to .syncro_db/.../audit.jsonl.
🧱
Sandboxed execution
Scripts run in isolated child processes; admin elevation is requested only for syncro install.

❓ FAQ & Troubleshooting

“syncro is not recognized” after install

PATH changes apply to new terminals. Close and reopen your terminal (or sign out/in). If it still fails, add the install folder to PATH manually and retry.

Do I need an internet connection or API key?

No. Cloning, analysing, reports, AST queries and known-fix reuse are all local. AI features are optional and use a local model endpoint when present.

Where is my data stored?

Per-project state lives in a .syncro_db folder; cross-project learning (known fixes, scripts, audit) lives under your user profile. Nothing leaves your machine unless you point Syncro at a remote model.

A command hangs — what do I do?

Press Ctrl+C. Add --timeout <seconds> to cap long steps, or --no-llm to skip the model entirely.

How do I see exactly what's available in my build?

Run syncro help. Commands marked Soon here may not appear yet.

Will it change my code without asking?

No. Mutating actions always show a preview and require approval (--yes), unless you explicitly opt into autonomous mode for safe, proven scripts.
