Introduction Core

syncro-cli.exe is a completely independent .NET 9 console application that runs in its own native Windows Terminal / PowerShell window. It communicates back to the Syncro Desktop agent via a Named Pipe IPC bridge, making it safe to crash, restart, and extend without ever risking the MAUI host process.

🔌
Fully Isolated Process
Spawned as a separate Process via UseShellExecute=true. Crashes in CLI never propagate to the Desktop app.
🪟
Win32 System Integration
Uses SendMessageTimeout P/Invoke to broadcast WM_SETTINGCHANGE after PATH updates — no reboot required.
🤖
AI-Aware Commands
syncro ai explain, syncro ai generate, and syncro ai patch call the local LLM with AST + Vector DB context.
📡
Status Reporting
Live status pushed from CLI to Desktop UI over a Named Pipe — visible in the Agent sidebar as real-time task updates.
📜
Extendable Scripts
Pre-written Bash/PS1 scripts bundled with the CLI. The AI can add new scripts at runtime via RAG hindsight learning.
🔐
UAC Elevation
Detects admin rights at startup. If missing, relaunches itself with verb="runas" for PATH registration tasks.

Full Command Reference 18 Commands

Every top-level command with subcommands, descriptions, and usage examples.

syncro init
Dev
Bootstraps a new Syncro workspace. Creates .syncro_db/, registers the project, and detects the tech stack automatically via the language/framework fingerprinting engine.
Examples
syncro init . syncro init ./myproject --name "Viking API"
syncro doctor
Info
Runs a complete environment health check: verifies Node.js, Python, .NET SDK, Git, Docker, database connectivity, and venv presence. Outputs a color-coded report.
Examples
syncro doctor syncro doctor --fix
syncro git
Dev
Safe Git wrapper that clones, pulls, and pushes repositories in a child process. Reports progress back to Desktop via Named Pipe. Clone failures never crash the host.
Examples
syncro git clone https://github.com/user/repo.git syncro git pull --rebase
syncro run
Dev
Detects the project type and runs its appropriate dev server: npm run dev, dotnet run, python manage.py runserver, flutter run, etc.
Examples
syncro run syncro run --port 5000 --env .env.local
syncro scan
System
Triggers a full AST scan of the current project. Nodes are parsed, context-filtered (separating build artifacts from source), and stored in SyncroDB/AST/.
Examples
syncro scan --depth 5 syncro scan --filter source
syncro graph
Info
Renders the dependency graph from the AST. Outputs Mermaid or DOT format. Supports cross-project group graphs for combo stacks like Next.js + MongoDB.
Examples
syncro graph --format mermaid syncro graph --output graph.dot
syncro ast
System
Directly queries the AST node store. Inspect specific symbols, list all classes, or find all usages of a method across the codebase.
Examples
syncro ast find TenderController syncro ast usages loginUser
syncro kb
DB
Manages the Knowledge Base within SyncroDB. Add, search, and list architectural notes, design decisions, and framework documentation snippets.
Examples
syncro kb search "JWT auth flow" syncro kb add --tag auth --file notes.md
syncro memory
AI
Views and manages the Agent Memory Store — past code generations, their success/failure status, and iteration counts. Used to guide future RAG-based suggestions.
Examples
syncro memory list --status failed syncro memory purge --older-than 30d
syncro ai
AI
The primary AI command. Integrates AST context, Vector DB search, and LLM inference. Supports explain, generate, find-auth-flow, patch, and review.
Examples
syncro ai explain TenderController syncro ai generate dto Tender
syncro project
System
Registers, lists, and removes projects from the SyncroDB Projects index. Supports grouping projects into combo stacks (e.g. Flutter + Next.js).
Examples
syncro project list syncro project group "MERN Stack" api frontend
syncro template
Dev
Lists and applies micro-architecture templates stored in SyncroDB — e.g. JWT Auth, Stripe Checkout, MongoDB Connector, Redis Cache.
Examples
syncro template list syncro template apply jwt-auth ./src/auth
syncro generate
AI
Scaffolds full boilerplate matching the detected language and framework conventions. Uses Memory Store to prefer generation patterns with success=true.
Examples
syncro generate controller Tender syncro generate service UserAuth --lang csharp
syncro patch
AI
Reads the last compiler error from SyncroDB/Errors/ and runs an AI-assisted auto-fix pipeline. Applies the patch, re-runs build, and updates memory on result.
Examples
syncro patch --last-error syncro patch --file src/controllers/auth.ts
syncro deploy
System
Pushes the project to configured cloud targets (Cloud Run, Azure App Service, Vercel). Reads deployment config from .syncro_db/deploy.json.
Examples
syncro deploy --target cloudrun syncro deploy --preview
syncro status
Info
Pushes the current CLI task status to the Syncro Desktop UI via Named Pipe. The Desktop sidebar shows live task progress without polling.
Examples
syncro status --msg "AST scan complete" --level success syncro status --task current
syncro install
System
Auto-elevates via UAC and registers syncro-cli.exe in the Windows Machine-level PATH. Broadcasts WM_SETTINGCHANGE so all open shells pick it up immediately.
Examples
syncro install syncro install --uninstall
syncro agent
AI
Invokes a multi-step autonomous AI agent task. The agent can chain AST scans, code generation, build verification, and auto-patching in a single session.
Examples
syncro agent "Refactor auth to use JWT refresh tokens" syncro agent --plan-only

Win32 PATH Installer Win32 API

Setting the Machine-level PATH environment variable requires Administrator rights and a WM_SETTINGCHANGE broadcast so that open shells (CMD, PowerShell, Windows Terminal) pick up the change without rebooting.

⚠ UAC Elevation Required: The installer checks for admin rights using WindowsIdentity.GetCurrent() and IsInRole(WindowsBuiltInRole.Administrator). If not elevated, it relaunches itself with verb = "runas".

Elevation Flow

→

→
Not Admin?
→

→

→

→

C# — Win32Api.cs 
public static class Win32Api
{
    // Broadcast WM_SETTINGCHANGE so all open shells pick up the new PATH
    [DllImport("user32.dll", SetLastError = true, CharSet = CharSet.Auto)]
    public static extern IntPtr SendMessageTimeout(
        IntPtr hWnd,     // HWND_BROADCAST = 0xFFFF
        uint   Msg,      // WM_SETTINGCHANGE = 0x001A
        IntPtr wParam,
        string lParam,   // "Environment"
        uint   fuFlags,  // SMTO_ABORTIFHUNG = 0x0002
        uint   uTimeout,
        out IntPtr lpdwResult);

    public static void BroadcastEnvironmentChange()
    {
        IntPtr result;
        SendMessageTimeout(
            new IntPtr(0xFFFF),  // HWND_BROADCAST
            0x001A,              // WM_SETTINGCHANGE
            IntPtr.Zero,
            "Environment",
            0x0002,              // SMTO_ABORTIFHUNG
            5000,
            out result);
    }

    public static void RegisterInSystemPath(string cliDirectory)
    {
        var current = Environment.GetEnvironmentVariable(
            "PATH", EnvironmentVariableTarget.Machine) ?? "";

        if (!current.Contains(cliDirectory, StringComparison.OrdinalIgnoreCase))
        {
            Environment.SetEnvironmentVariable(
                "PATH",
                current + ";" + cliDirectory,
                EnvironmentVariableTarget.Machine);

            BroadcastEnvironmentChange();
        }
    }
}

Shell Runner Core

ShellRunner.cs is the execution abstraction layer. It wraps PowerShell and Bash invocations, captures stdout/stderr, streams output to the Named Pipe bridge in real-time, and records exit codes.

Method Shell Use Case Return
RunPowershell(script) PowerShell 7+ Node install, PATH scripts, Windows automation ShellResult { ExitCode, Stdout, Stderr }
RunBash(script) Git Bash / WSL Python venv, Linux-compatible setup scripts ShellResult { ExitCode, Stdout, Stderr }
RunAndStream(cmd, pipe) Any Real-time output streaming to Desktop UI via Named Pipe Async IAsyncEnumerable<string>
RunElevated(exe, args) OS Shell Admin-required operations (PATH write, service install) Process handle

Build Pipeline MSBuild

The CLI is compiled automatically every time Syncro.Desktop is built, via a post-build MSBuild target. The output binary is copied directly into the Desktop's output directory.

XML — Syncro.Desktop.csproj (Post-Build Target) 
<Target Name="BuildCLI" AfterTargets="Build">

  <!-- Step 1: Compile the standalone CLI console project -->
  <MSBuild
    Projects="Syncro.CLI/Syncro.CLI.csproj"
    Targets="Publish"
    Properties="PublishSingleFile=true;SelfContained=false;RuntimeIdentifier=win-x64" />

  <!-- Step 2: Copy exe to Desktop output so it launches alongside the app -->
  <Copy
    SourceFiles="Syncro.CLI/bin/Release/net9.0/win-x64/publish/syncro-cli.exe"
    DestinationFolder="$(OutputPath)"
    SkipUnchangedFiles="true"
    ContinueOnError="true" />

</Target>
💡 PublishSingleFile: The CLI is published as a single self-contained .exe file. No additional runtime DLLs are needed — just copy and run. Add the output directory to PATH and syncro works globally.

AI Command Pipeline AI + RAG

Every syncro ai * subcommand follows a multi-stage retrieval-augmented generation pipeline that pulls context from AST nodes, Vector DB similarity search, and the Agent Memory Store.

1. Parse CLI Query
— Extract intent: explain / generate / find / patch
2. AST Symbol Lookup
— Fast O(1) index lookup in SyncroDB/AST/
3. Vector Similarity
— Cosine match in SyncroDB/Vectors/ for semantic context
4. Memory RAG
— Inject past successful generations as few-shot examples
5. Prompt Assembly
— Merge AST + Vectors + Memory into structured LLM prompt
6. LLM Inference
— Call local or cloud LLM endpoint, stream output to terminal
7. Save to Memory
— Log result to SyncroDB/Memory/ for hindsight learning

Named Pipe Bridge IPC

The CLI and Desktop communicate via a local Windows Named Pipe. The Desktop hosts a NamedPipeServerStream; the CLI connects as a client and pushes JSON status packets. This is fully non-blocking — the Desktop reads on a background thread.

Packet Type Fields Triggered By
status level, message, taskId syncro status, any long-running command
progress percent, step, total AST scan, clone, generate
error code, message, file, line Build failures, parser errors
result type, data, durationMs AI generate, graph render
heartbeat pid, timestamp Every 5 seconds while CLI is running

Pre-Written Scripts Bundled

The CLI ships with a Scripts/ directory containing environment automation scripts. The AI can generate and register new scripts at runtime via RAG hindsight.

Script Shell Purpose
setup-venv.sh Bash Detects Python version, creates .venv, installs requirements.txt
install-node.ps1 PowerShell Checks Node.js, installs via winget or nvm-windows
check-db.sh Bash Pings SQL/NoSQL hosts, reports latency and connection status
clone-repo.ps1 PowerShell Safe git clone in child process; reports status via Named Pipe; never crashes host
add-to-path.ps1 PowerShell Admin-elevated PATH registration + WM_SETTINGCHANGE broadcast
🤖 AI-Extendable: When syncro ai generate script creates a new helper script, it is saved to SyncroDB/Memory/ and registered in the script index. On the next run, the RAG engine can suggest it as a reusable asset.

Security & UAC Model Security

🔐
Principle of Least Privilege
The CLI runs as a standard user by default. Elevation is only requested for PATH registration (syncro install). All other commands require no admin rights.
🛡️
Process Isolation
Scripts run in child Process objects with explicit environment variable sandboxing. The CLI process cannot access the MAUI app's memory space.
🔑
Credential Safety
API keys and DB URLs are stored in the user's SyncroDB config with file-system ACL protections. Never logged to stdout or the Named Pipe stream.
📋
Audit Logging
Every elevated command and PATH change is logged to SyncroDB/Agents/audit.jsonl with timestamp, user, and operation details.
