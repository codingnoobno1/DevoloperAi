Introduction Embedded DB

SyncroDB is not a remote database service — it is a local, filesystem-native database that lives inside the user's configured Syncro workspace directory (.syncro_db/). It requires no Docker, no server process, and no network — it's just fast, structured JSON + flat binary vector files, managed by the Syncro Desktop agent and CLI.

📍 Location: SyncroDB lives at <workspace>/.syncro_db/. For example: D:/DeveloperAI/DEVOLOPER/.syncro_db/. It is automatically initialized by syncro init or the first AST scan.
🔍 Design Philosophy: Every file in SyncroDB is human-readable JSON. The vector embeddings are stored as compact float arrays in .vec binary files, indexed by a JSON sidecar. This makes the DB inspectable, debuggable, and trivially exportable.

Namespace Catalog 11 Namespaces

Each namespace is a dedicated directory with a clearly defined schema and access pattern.

🌳
AST/
.syncro_db/AST/<project_id>/
Stores parsed AST node maps: classes, functions, imports, REST routes. Context-filtered to exclude build artifacts (.next/, bin/, node_modules/). Supports O(1) symbol lookup via ast_index.json.
🕸️
Graphs/
.syncro_db/Graphs/<project_id>/
Kahn topological sort DAGs and call graphs. Exports to DOT and Mermaid. Supports cross-project edges for combo stacks (e.g. Next.js frontend → Express API → MongoDB).
🧮
Vectors/
.syncro_db/Vectors/<project_id>/
Semantic embeddings for functions, classes, REST endpoints, and database schemas. Stored as binary float32 arrays (768 or 1536 dimensions). Queried via cosine similarity for RAG retrieval.
🧠
Memory/
.syncro_db/Memory/
Agent hindsight learning store. Every code generation is logged with its outcome (success: true/false), iteration count, and compiler errors. Guides future RAG-based few-shot injection.
💥
Errors/
.syncro_db/Errors/
Compiler error logs from all build attempts (dotnet build, npm run build, flutter build). Used by syncro patch to locate the last failure and apply AI auto-fix.
📐
Templates/
.syncro_db/Templates/
Reusable micro-architecture templates. Each template contains boilerplate files for a specific concern (JWT Auth, Stripe Checkout, MongoDB Connector). Applied via syncro template apply.
📚
Frameworks/
.syncro_db/Frameworks/
Static framework knowledge base: file naming conventions, standard directories, CLI commands, and common patterns for 30+ languages and frameworks. Powers the FrameworkKnowledgeStore.
🏛️
Architectures/
.syncro_db/Architectures/<project_id>/
Discovered architectural patterns per project. The AST engine detects MVC, Clean Architecture, Onion, Hexagonal, and Microservice patterns and stores layer maps here.
🤖
Agents/
.syncro_db/Agents/
Checkpoint logs and audit trails for multi-step agent tasks. Every elevated CLI operation (PATH install, service registration) is logged to audit.jsonl for security review.
📁
Projects/
.syncro_db/Projects/
Master registry of all Syncro-managed projects. Stores path, language, framework, detected architecture, and linked group IDs. The primary lookup table for all cross-namespace queries.
🔗
Groups/
.syncro_db/Groups/
Multi-project combo configurations. Links frontend + backend + database projects into a named stack (e.g. "MERN", "Flutter + Next.js", "Rust + Flutter"). Enables cross-project graph queries.

Hybrid Search Architecture 3-Mode Query

SyncroDB implements a three-stage hybrid search pipeline. All three modes can be composed in a single query.

1
Exact Symbol Search (O(1))
Direct lookup via AST/<project_id>/ast_index.json. Finds classes, methods, routes, and imports by exact name. Used by syncro ast find and syncro ai explain. Sub-millisecond response.
2
Metadata Filter Query
Filter vector records by structured metadata: project_id, framework, language, node_type, or tags. Narrows the search space before running cosine similarity. Implemented as in-memory JSON predicate evaluation.
3
Cosine Similarity Search (Semantic)
Embeds the query string, then scans filtered embeddings.vec binary files for the top-K nearest vectors using cosine similarity. Supports cross-project search when a group_id filter is applied.
4
Result Aggregation & Re-ranking
Results from AST and vector search are merged, de-duplicated, and re-ranked using a combined score: score = 0.6 × semantic_similarity + 0.4 × ast_proximity_score. Top results are injected as RAG context into the LLM prompt.

Project Combos & Cross-Project Queries Multi-Project

When projects are grouped into a combo, SyncroDB builds cross-project dependency edges. The AI agent can then answer questions that span both frontend and backend boundaries.

Example Cross-Project Query: "Which MongoDB collection is written to when the user submits the login form on the Next.js frontend?"

SyncroDB traverses: Next.js page handler → fetch POST /api/auth/login → Express route → loginUser() → MongoDB users.insertOne() — across 3 separate project ASTs using the Group cross-project graph.
